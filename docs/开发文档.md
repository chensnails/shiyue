# 拾阅（shiyue）开发文档

> 面向开发者与维护者的技术文档：架构、数据模型、权限、部署与版本发布。
> 面向普通用户的说明见 [README.md](../README.md)。

---

## 1. 项目定位

拾阅是一个**自托管的 RSS 阅读器**，特征：

- 左侧频道（按分组）、右侧文章，点标题就地展开全文；另含资源卡片墙与每日 AI 简报。
- **多用户**：每人独立的订阅源 / 已读 / 收藏 / 日报，互不干扰。
- 数据存 **PostgreSQL**，无广告、无遥测。
- 模型配置 **按账户绑定**：每个用户用自己的 Key 调大模型，未配则回退站点默认。

---

## 2. 技术栈

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 运行时 | Node 22 | 仅用内置模块 + `pg` + `undici` |
| 数据库 | PostgreSQL | 主存储，含按用户隔离的数据 |
| 前端 | Vite + React | 入口在仓库根；界面与核心逻辑都在 `src/`，`public/` 静态资源原样拷入 `dist/` |
| 离线 | Service Worker | `public/sw.js`，PWA 安装 |
| 部署 | Docker Compose | 1Panel 管理；OpenResty 反代 + Cloudflare |

**前端构建**：Vite 多页面双入口（`index.html` / `login.html`），`public/` 经 `publicDir` 原样拷入 `dist/`；界面与核心逻辑全部在 `src/`，打进 bundle（v2.0.0 起不再有并行的经典脚本，见 §8）。

## 4. 本地运行 / 构建 / 部署

### 本地

```bash
cp .env.example .env        # 至少改 PG_PASSWORD
docker compose up -d --build
# 访问 http://<主机>:3210，默认 admin / admin
```

### 生产更新

在部署主机把项目目录设为 git 工作树，一条命令：

```bash
cd <项目目录>
./deploy.sh
```

- **前端 / 后端任何改动**：都要 `docker compose up -d --build` 重建镜像——前端 `dist/` 已打进镜像（不再挂载 `./public:/app/public`），ARM 服务器构建约 +30~60s。
- **本地纯前端联调**：`npm ci && npm run dev`（Vite 5173，`/api` 自动代理到本地 3000 后端；后端需另行 `node server.js` 或 compose 启动）。
- 页面不主动提示更新（v1.10.1 起移除了「新版本已发布」提示条）；旧标签页需手动刷新才能拿到新代码。

> 部署主机通过 SSH 登录操作；密钥与主机地址属于运维敏感信息，不在本文档与仓库中存储（见 `.workbuddy/` 已 gitignore）。

## 5. 数据模型（PostgreSQL）

隔离是**数据库层面**的，而非查询时过滤。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `users` | `id, username, pass_hash, role, prefs(JSONB)` | `role` ∈ `admin`/`user`；`prefs` 存外观、布局、**模型配置**等按账号偏好 |
| `feeds` | `id, owner_id, url, title, custom_title, group_name, refresh_minutes, ...` | `owner_id` 决定归属 |
| `entries` | `id, feed_id, title, link, content, is_read, is_fav, ...` | 经 `feed_id` 归属到用户 |
| `settings` | 站点级单行 | 含 `llm`（站点默认模型）、采集参数、日报参数 |
| `digests` | 主键 `(owner_id, date)` | 每个用户每天一份日报 |

`prefs` 为 JSONB，子对象含 `appearance` / `layout` / `llm` 等，按账号持久化，换设备登录一致。

## 6. 账户与权限

- 角色：`users.role` = `admin` | `user`。
- 判定：`isAdmin(user)`。
- 权限矩阵：

| 能力 | 管理员 | 普通用户 |
| --- | --- | --- |
| 阅读 / 管理自己的订阅源 | ✅ | ✅ |
| 个人外观 / 布局 | ✅ | ✅ |
| **个人模型配置** | ✅ | ✅ |
| 生成自己的 AI 日报 | ✅ | ✅ |
| 用户管理（`/api/users`） | ✅ | ❌ |
| 站点级设置（采集参数 / 状态 / 日报设置 / 模型站点默认） | ✅ | ❌ |

- 账号只能由管理员创建（无开放注册）。
- 删除用户级联删除其订阅源 / 条目 / 日报；系统拦截「删最后一个管理员」「删除自己」。

### 模型配置按账户绑定

- 每个用户的 Key 存 `users.prefs.llm.apiKeyEnc`，经 `encryptSecret` 以 `cryptoSecret` 加密落库，页面只回显掩码、不回显明文。
- 解析函数 `resolveUserLlm(user)`：**用户自己配的优先；未配则回退站点 `settings.llm` 默认**。
- AI 调用（`digest.js` 的 `chat/singlePass/mapReduce/generate/testLlm`）支持透传 `llmOverride`，使每个用户的日报用各自的模型。
- 前端「设置 → 模型」普通用户可见，读写走 `/api/prefs`（不再是 admin-only 的 `/api/config`）；用户管理 / 采集 / 状态 / 日报设置仍仅管理员。

## 7. 关键模块

- **server.js**：单进程 HTTP。负责路由分发、静态资源（`serveStatic` 从 `dist/` 读盘，未构建时回退 `public/`；每次读 + `Cache-Control: no-cache`）、登录态注入、定时调度（抓取 / 日报）、权限中间件。AI 端点（`/api/digest/generate`、`/api/digest/test-llm`）按当前账号解析模型配置。版本检测端点：`GET /api/version`（当前版本，读 `package.json`）与 `POST /api/version/check`（向 GitHub 查最新 Release，未发 Release 则回退 Tags；结果缓存 10 分钟；支持环境变量 `GITHUB_REPO` / `GITHUB_TOKEN`）。
- **db.js**：连接池 + 迁移（首次启动建表、把单用户旧账号迁为首个管理员，幂等）+ 按用户隔离的 CRUD。
- **rss.js**：解析 RSS 2.0 / Atom / RDF，产出「图文顺序块」（连续图片拼网格、文字片段按出现顺序），保证图文原样呈现。
- **digest.js**：日报生成。`generate({ ownerId, feeds, date, force, llm })` → 单批或 map-reduce → 结构化摘要；按 `(owner_id, date)` 落库。
- **proxy.js**：出网代理，图片（`/api/img`）与抓取请求经它转发，规避源站防盗链与出网限制。

## 8. 前端架构

- `index.html` 是登录后的应用壳；`login.html` 是独立登录页（未登录访问 `/` 会 302 到登录页）。两者是 Vite MPA 的构建入口（在仓库根），产物进 `dist/`；`dist/` 之外的静态资源由 `publicDir`（`public/`）原样拷入。
- 全部前端代码都在 `src/`，由 `index.html` 里唯一的 `<script type="module" src="/src/main.jsx">` 加载（`main.jsx` 先 `import '@core'` 初始化核心，再挂载各组件）。模块脚本带 defer、晚于 DOM 解析执行，所以核心可以放心在顶层查询 DOM。
- 视图：文章（reader）/ 卡片（cards）/ AI（ai）。`switchView` 用 View Transitions API（尊重 `prefers-reduced-motion`）。
- **架构总览（v2.1.0 起）**：核心逻辑拆在 `src/core/` 下 8 个 ES 模块，**依赖单向无环**：`util.js`（纯工具 / apiFetch / toast）→ `state.js`（全局 state、偏好 layout/appearance/theme、滚动锁、设置弹层开合）→ `feeds.js`（频道加载 / 卡片列表分页 / 筛选 / 视图模式）→ `reader.js`（文章视图数据、抽屉 / 手势 / 无限滚动 / 键盘导航）→ `autorefresh.js`（定时刷新与新内容浮标）→ `ui.js`（刷新 / OPML 导出 / `switchView` / 灯箱 / 分组折叠 / 安装提示 / 键盘导航 / `shellSnapshot`）→ `bootstrap.js`（首屏主题与视图应用、登录态校验、首次加载、深链定位）→ `index.js` 汇总成 `core` 单例。组件统一 `import { core } from '@core'`。
- **视图与核心的协作方式**：视图只做渲染；控件调用 `core.*` 改共享 state；核心在需要刷新 UI 时派发窗口事件，组件监听后重读实时 state 重绘：
  - `__cardsTick` → 卡片视图（`src/views/CardsView.jsx`）
  - `__readerTick` → 文章视图（`src/views/ReaderView.jsx`）
  - `__shellTick` → 顶栏 / 进度条（`src/shell/TopBar.jsx`）
  - `__viewChanged`（detail = 视图名）→ 切视图时通知 AI 视图激活 / 隐去
  - `__appearanceChanged` → 外观偏好外部改动回流到外观面板
- **历史沿革（渐进迁移，已收官）**：P0 脚手架 ✅ → P1 命令面板 ✅ → **P2 设置弹层**（P2a 外壳 + 外观 / 关于，P2b 模型，P2c 数据源，P2d 账号 / 状态 —— 六个面板全部 React 化，legacy-slot 机制退役）→ **P3 三大视图**（P3a AI、P3b 卡片、P3c 文章）→ **P4 收尾**（P4a App Shell 顶栏 + 进度条 → P4b 核心逻辑迁入 `src/core/`、拆除 `window.shiyue` 桥、`public/app.js` 退役，tag **v2.0.0**）。CSS 与主题零改动：React 组件直接复用类名。
  - **⌘K / Ctrl+K 命令面板**：已 React 化（`src/cmdk/`：`pinyin.js` 拼音表、`commands.js` 命令构建与过滤、`CommandPalette.jsx` 组件；键位 / 拼音过滤 / 类名与原实现逐行等价）。
  - **设置弹层**：外壳与「数据源 / 模型 / 账号 / 外观 / 状态 / 关于」六个面板全部 React 化（`src/settings/`：`SettingsModal.jsx` 外壳、`SourcePane.jsx` 数据源表单、`ModelPane.jsx` 模型表单——受控状态 + temperature 数值化，Key 永不回填明文、留空 = 不修改、`AppearancePane.jsx` 配置驱动外观表单、`AccountPane.jsx` 账号与用户管理、`StatusPane.jsx` 只读体检页、`AboutPane.jsx` 版本号与检查更新）。外观选中态由 React 从偏好数据推导，外部改动经 `window.__appearanceChanged` 事件回流；旧 `openSettings` / `closeSettings` 委托宿主 `window.__settingsHost`。P2d 起 `#legacyPanes` 隐藏容器与 `.tab-pane-legacy` 搬运机制、`settingsTabEffect` / `getLegacySettingsPane` / `stopStatusPolling` 等旧桥函数一并退役，开合状态仍经 `window.__settingsOpen` 同步给旧键盘导航 / 自动刷新守卫。
    - **SourcePane 数据流约定**：频道数据以共享 state（`feedList` / `feedMeta` / `groupOrder`，均原地修改、实时引用）为单一数据源，原地改动后 bump tick 重绘，服务端往返统一走核心单例 `loadFeeds()` 刷新再 bump；拖拽用 Pointer 事件（`dragRef` + `moveRef`/`endRef` 保证监听器同一引用），频道重排 / 跨组落库 `/api/feeds/reorder`，分组重排落库 `/api/prefs`；`cfgLoaded` 复刻旧 `srcFormReady` 守卫（配置没拉到禁止保存）；行内控件保存期间 `pendingIds` 逐控件禁用、失败回滚。v1.5.0 同修复服务端 `GET /api/config` 漏返 `source.proxyUrl` 导致代理设置被清空的 bug。
    - **AccountPane / StatusPane（P2d）**：账号面板表单受控，用户管理（增删 / 改角色 / 重置密码，仅管理员，危险操作走 `confirm` / `prompt`）操作后重拉 `/api/users`；状态面板进入即拉 `/api/status` 快照并每 30s 轮询、「已运行时长」本地每秒递增（轮询与递增定时器随组件 `useEffect` 挂载 / 卸载自洽启停），「复制诊断」把快照拍平成纯文本（剪贴板降级兜底），异常频道逐个重试；格式化函数（时长 / 字节 / 相对时间 / 千分位）下沉为组件内纯函数，可折叠分组开合复用核心单例 `bindSections`。
  - **AI 视图（P3a）**：视图内容迁往 `src/ai/AiView.jsx`，挂载到 `index.html` 的 `#aiRoot`（外层 `#aiView` 容器仍由旧 `switchView` 显隐，切到 AI 时经 `window.__viewChanged` 事件通知组件激活）。日报子页进入即拉 `/api/digests` 与所选日期摘要（概览 / 元信息 / 亮点 / 分组条目全部 JSX 渲染，含空态 / 加载 / 读取失败 / 生成失败；条目复制按钮与缩略图兜底由 React 处理，替代旧 `bindCardActions`），日期下拉切换与生成 / 重新生成走 `/api/digest/generate`；日报设置子页（仅管理员）为 `/api/config` 的 `digest` 段受控表单。子页光标按账号持久化（`users.prefs.layout.aiPage`），经核心单例 `getAiPage` / `setAiPage` 读写。
  - **卡片视图（P3b）**：视图内容迁往 `src/views/CardsView.jsx`，挂载到 `#cardsRoot`。**数据 / 状态仍归 core**（`state.entries` 等 + `loadPage` + 自动刷新 + 收藏 PATCH），组件只做渲染，控件经核心单例 `cardsSearch` / `cardsFilterFeed` / `cardsSort` / `cardsSize` / `cardsView` / `cardsTag` / `cardsLoadMore` / `cardsSetFlag` 改共享 state；core 需刷新卡片 UI 时派发 `window.__cardsTick`，组件监听后读实时 state 重绘（沿用 SourcePane 的「共享状态 + tick」约定）。跨视图共享机制仍留 core：自动刷新 / 新内容浮标、`j/k` 键盘导航（查 `#grid`）、收藏已读、`/` 聚焦（经 `window.__cardsFocusSearch` 委托组件）。
  - **两种迁移范式**：① **自持状态**（`src/ai/AiView.jsx`——组件自己拉数据、自己管状态，适合低耦合视图）；② **共享状态 + tick**（`src/views/CardsView.jsx`——数据 / 逻辑留在 `core`，组件只渲染，控件经 `core.*` 改 state、core 派发事件触发重绘，适合与核心高度共享的视图）。文章视图（`src/views/ReaderView.jsx`）亦为范式 ②（与卡片页共享自动刷新 / 键盘导航 / 收藏 / 抽屉手势）。
  - **UI 回归测试**：`tests/ui/`（jsdom 运行时挂载真实 React 组件），`npm run test:ui` 先用 esbuild 打包 `mount-*.jsx` 到 `tests/ui/.build/`（gitignored），再由 `ui-regression.cjs` 断言；当前 **204 项全绿**，覆盖设置弹层六面板 / AI 视图 / 卡片视图 / 文章视图 / App Shell 顶栏 / 覆盖层，以及真实核心模块的顶层加载冒烟。
  - **文章视图（P3c）**：视图内容迁往 `src/views/ReaderView.jsx`，挂载到 `#readerRoot`。数据 / 逻辑仍归 core（`state.rdEntries` / `rdExpanded` / `rdBody` 等 + `loadReader` + 已读收藏 + 抽屉 + 手势 + 无限滚动 + 键盘导航），控件经核心单例 `readerSetScope` / `readerSetFeed` / `readerSetGroup` / `readerSearch` / `readerToggleArt` / `readerToggleFav` / `readerCollapseAll` / `readerReadAll` / `readerTagToCards` / `readerToggleAccordion` / `readerToggleDrawer` / `readerCloseDrawer` / `readerOpenSource` 改 state，core 派发 `window.__readerTick` 重绘。正文分段纯函数（`splitLongLine` / `bodyParagraphs` / `parseBlocks`）已下沉组件。
  - **App Shell 顶栏 / 进度条（P4a）**：顶栏与阅读进度条迁往 `src/shell/TopBar.jsx`，顶栏挂载到 `#topbarRoot`（即 `<header class="topbar">` 本身，组件只渲染其内部内容）、进度条挂载到 `#shellRoot`（须在 header 之外——`.topbar` 的 `backdrop-filter` 会成为 fixed 后代的包含块）。数据经核心单例 `getShell()` 一次性快照读取，core 派发 `window.__shellTick` 通知重绘；交互经核心单例 `switchView` / `refresh` / `cycleTheme` / `openSettings` / `promptInstall`。刷新按钮忙态（禁用 + 图标自旋）由组件本地维护，core 侧抽为 `refreshFeeds()`；「顶栏高度 → `--topbar-h`」与进度条滚动驱动（rAF 节流）亦下沉组件。

## 9. 反向代理 gzip

站点经 1Panel + OpenResty 反代，已开启 gzip（含 `gzip_proxied any`，否则反代响应默认不压缩）。配置片段（宿主机 `conf.d` 的站点 server 块内）：

```nginx
gzip on;
gzip_comp_level 6;
gzip_min_length 1024;
gzip_proxied any;
gzip_vary on;
gzip_types text/plain text/css text/javascript application/javascript application/json application/xml image/svg+xml font/woff2;
```

改完 `nginx -t && nginx -s reload` 生效。

## 10. 版本管理与发布

遵循 [语义化版本](https://semver.org/lang/zh-CN/) `主版本.次版本.修订号`：

- **MAJOR**：不兼容的架构 / 接口变更（如破坏性数据库迁移）。
- **MINOR**：向后兼容的新功能。
- **PATCH**：向后兼容的问题修复。

### 发布流程

1. 在 `main` 完成改动并合并。
2. 更新 `CHANGELOG.md`，新增对应版本条目。
3. 同步更新 `VERSION` 文件与 `package.json` 的 `version` 为同一版本号。
4. 打标签并推送：
   ```bash
   git tag -a vX.Y.Z -m "vX.Y.Z"
   git push origin main --tags
   ```
5. 服务器拉取并重建：登录部署主机执行 `./deploy.sh`。

> `main` 始终是可发布的稳定分支；后续更新一律按此版本号流程推进。

## 11. 常见开发坑

- **模块顶层 TDZ**：`src/core/*.js` 是 ES 模块（等价 defer，DOM 解析完成后才执行）；函数 / 常量必须先声明后引用。
- **视口单位**：移动端用 `dvh` 而非 `vh`，避免地址栏伸缩导致布局跳动。
- **滚动锁**：弹层（命令面板 / 设置）打开时锁背景滚动，关闭恢复。
- **图标基类**：所有图标走 SVG sprite，新增图标加 `<symbol>`。
- **主题 token**：配色集中由 `tools/gen-theme.mjs` 生成，不要手写散落的色值。
- **图文块渲染**：`rss.js` 产出图文顺序块，前端按块渲染，勿把图文拆散。
- **密钥**：`.env` 与 `.workbuddy/` 已 gitignore，任何密钥、主机地址、私钥路径都不要写入仓库或本文档。

## 12. 环境变量（`.env`）

除端口与数据库外，其余项**首次启动后一律以页面「设置」为准**，再改 `.env` 不生效。关键变量见 `.env.example`：

- `HOST_PORT` 宿主机映射端口（默认 3210）
- `PG_DB` / `PG_USER` / `PG_PASSWORD` 数据库（密码必填）
- `SEED_FEEDS` 首次启动播种的 RSS 地址（逗号分隔）
- `REFRESH_MINUTES` 自动抓取间隔
- `KEEP_PER_FEED` / `KEEP_DAYS` 保留策略（收藏永久豁免）
- `LLM_BASE` / `LLM_KEY` / `LLM_MODEL` 站点级大模型默认（也可页面配）
- `DIGEST_ENABLED` / `DIGEST_TIME` / `DIGEST_SCOPE` 日报开关 / 时间 / 范围
- `ADMIN_USER` / `ADMIN_PASS` 首个管理员（仅首次启动生效）
